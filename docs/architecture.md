# RecallMemory 项目架构

## 产品边界

RecallMemory 是独立于 Agent 的经验记忆与重复错误防护平台。它不调用模型、不替 Agent 执行动作，也不会自行判定一条经验为可信事实。

```text
桌面客户端 / 任意 Agent
          |
      HTTP 或 MCP
          |
       传输适配层
          |
   记忆服务 -------- 领域适配器
       |                 |
       +------ 存储层 ---+
                |
              SQLite
```

桌面端是本地服务和信任生命周期的管理入口。Agent 可以提交候选经验，但不能通过 MCP 把自己的候选经验提升为已验证记忆。首版由可信桌面流程或受控 HTTP 调用完成验证。

## 构建目标

| 目标 | 职责 |
| --- | --- |
| `recall_memory_core` | 领域模型、SQLite 存储、召回排序、防重复策略和 C/C++ 图谱适配器 |
| `recall_memory_transport` | HTTP 与 MCP 协议适配 |
| `RecallMemory.exe` | 唯一发布程序；原生 Windows UI 及进程内 HTTP/MCP 服务 |
| `recall_memory_tests` | 解析、增量存储、通用召回及防重复测试 |

业务规则不属于传输层。模块继续保持独立 CMake target，便于测试和演进，但这些内部边界不再暴露为多个发布程序。

## 源码布局

所有产品源码统一放在 `src` 目录，并按职责分为前端和后端：

```text
src/
├── frontend/desktop/          Windows 桌面界面与程序入口
└── backend/recall_memory/     HTTP、MCP、记忆、存储、Code Graph 与领域模型
```

这里的前端和后端是同一个 `RecallMemory.exe` 进程内的代码边界，不是两个程序，也不会产生独立的后端可执行文件。`tests` 只存放测试代码，`cmake` 只存放构建配置。

## 记忆空间与数据模型

`workspaceId` 是记忆空间的隔离键，不限定为代码仓库。一个记忆空间可以代表项目、团队、用户、业务域或长期运行的 Agent。SQLite 保存四类数据：

1. `workspaces`：记忆空间及可选本地目录身份。
2. `experiences`：持久经验及其信任生命周期。
3. `experience_feedback`：有用、过时、错误等反馈。
4. `graph_files`、`graph_nodes`、`graph_edges`：可删除并重建的代码图谱索引。

经验是产品数据，重建图谱时不得删除。每条经验包含触发条件、现象、根因、处理摘要、未来必须保持的不变量、证据、验证步骤和作用域。

通用作用域包括 `agent`、`context`、`resource`、`entity`、`workflow`、`domain` 和 `tag`。编码适配器额外使用 `file`、`symbol` 与 `module`。

## 信任生命周期

```text
Agent 或用户提交
       |
       v
   candidate --------> retired
       |
   可信证据验证
       v
    verified ---------> stale
       ^                  |
       +---- 重新验证 ----+
```

普通召回和防重复检查默认排除候选经验。这样可以避免失败任务、提示注入或 Agent 自我确认把错误结论固化为长期事实。

## 召回与防重复流程

```text
任务 + Agent + 上下文 + 资源 + 实体 + 流程
                  |
      文本相关度 + 直接作用域 + 信任度
                  |
          可选领域适配器扩展信号
                  |
              排序后的经验
                  |
       聚合不变量、验证步骤和风险提示
```

每个召回结果都携带评分原因，调用方可展示原因并记录是否有用。防重复检查既可用于代码变更，也可用于报告生成、客服处理、数据操作、办公自动化等任务结果。

## Code Graph 适配器

Code Graph 只是编码领域的增强信号。没有代码图谱时，通用记忆仍可正常存储、召回和防护。

首版用 Tree-sitter 提取 C/C++ 文件、命名空间、类、结构体、枚举、函数、方法、包含关系和语法级调用关系。稳定标识基于工作区、文件、符号类型、限定名和函数声明，单纯修改函数体通常不会改变标识。

Tree-sitter 不进行编译和重载解析，因此图谱边包含证据与置信度。未来可通过统一领域适配器接口引入 Clang、LSP、知识图谱、业务实体图或工作流图。

## Coding 模式

RecallMemory 应提供 Coding 模式，但模式只负责选择能力配置，不建立另一套记忆内核或数据库。

通用模式默认隐藏代码专用工具，只按任务、Agent、上下文、资源、实体、流程和显式作用域召回。Coding 模式在相同召回流程上额外启用：

- 工作区增量索引和 Code Graph 邻接扩展；
- `file`、`symbol`、`module`、错误签名和变更摘要信号；
- 开始编码前召回、确定修改范围后检查、生成最终差异后再次检查三个任务钩子；
- `bug_fix`、`architecture_decision`、`failed_approach` 等编码经验模板；
- 面向测试命令、不变量和历史回归的结果展示。

模式应属于 MCP 连接或 Agent 会话，而不是永久写死在经验记录上。同一个记忆空间可以被不同类型的 Agent 使用，经验仍通过通用作用域共享。未来增加运维、研究或浏览器自动化模式时，也只需注册新的领域适配器和任务钩子。

## 桌面程序

Windows 桌面端是唯一产品入口。点击“启动服务”后，UI 进程直接构造 SQLite、记忆服务、Code Graph、HTTP 和 MCP 对象，并用内部工作线程监听本机端口；不会启动或依赖任何子进程。关闭窗口会停止工作线程并释放数据库。默认数据库位于 `%LOCALAPPDATA%\RecallMemory\recall-memory.db`。

首版 UI 负责服务生命周期和连接地址。后续在同一个程序内增加记忆审核、召回解释、冲突合并、过时记忆清理和领域适配器管理。

## 安全决策

- 服务默认只监听 `127.0.0.1`。
- MCP 不提供经验验证工具，Agent 不能自行提升信任等级。
- RecallMemory 只返回建议验证步骤，不自动执行命令或外部动作。
- SQLite 启用 WAL 和五秒忙等待；HTTP 与 MCP 在同一 UI 进程内共享存储实例。
- 暴露到非本机地址前，必须增加身份认证、授权策略与传输加密。
